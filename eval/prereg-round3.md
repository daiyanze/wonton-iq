# 预注册 — 第三轮混合检索实验（BM25 + 稠密腿：托管 embedding vs 本地 BGE-M3）

> 日期：2026-11-14（本文件写于新题编写与任何第三轮模型调用之前；文件顺序：本预注册 → `questions-v3-additions.json` → `run_s5.py`，三者按此顺序落盘，便于事后核对没有看题后改规则。）
> 纪律同第一、二轮（`README.md`、`prereg-round2.md`）：规则先写死，跑完照此判定，不改口径。

## 背景与目的

第二轮校准后，线上系统已定版为 **S2-cal**：BM25 全部命中块作候选 → JEV 单轮逐块打 Noul 概率 → noul ≥ 0.8 的块拼答，否则兜底。已知成绩：v1 集 50/55、v2 新题集 39/45，兜底 D+E 两集都过 90%，编造 0。

同日完成的行业调研（`~/workspace/research_notes/ai-support-retrieval-mainstream-best-pra-20261114-1302/report.md`）给出的定位是：本系统在“弃答/防编造”轴上与最佳实践同向甚至更保守，但**落后在召回轴**——主流生产方案（混合检索 BM25∥稠密 + 重排）的另一条腿我们没有。实测弱点与调研判断吻合：

- 英文改写题与原文词面重合太低时，BM25 候选可以为**零**（第二轮 V2B01 即无候选 miss），JEV 再准也没机会判定；
- 中文题在 `app.tokenize` 阶段就被英文字母分词滤空（FTS5 unicode61 把整串 CJK 当一个 token），v1 中文组两轮都是 0/5；
- 日文从未测过。

本轮只验证一件事：**给候选生成加一条稠密（embedding）腿、其余全部不动，能否把改写/中文/日文三组的召回补上，同时不破坏已经过线的兜底与回归。** 两条 embedding 路线（托管 API 与本地自托管）同台对照，由 Dai 拍板“两条都进实验对照，数据说话”。

## 唯一变量（本文件写下后冻结）

只动**候选生成**一处：

- 候选池 = BM25 全部命中块 ∪ 稠密 top-8（按余弦相似度降序截断 8 块），按 chunk id 去重；
- 被 JEV 接受的块，拼答顺序按 **RRF（k=60）** 融合两条排名表决定：BM25 表 = 现行全部命中块按 bm25 升序；稠密表 = 全部块按余弦降序、截断 8 名。块在某条表中缺席则该表不贡献分数；RRF 同分时先按其在任一表中的最好名次、再按 chunk id 定序（保证可复现）；
- JEV 门控与线上**逐字一致**：同一 Noul instructions / criteria、每题全部候选打包一次请求、接受线 noul ≥ 0.8；拼答（原文拼接 + 出处去重）与兜底行为不变；
- 对照臂（S2-cal）的候选池与拼答顺序就是现行线上行为（BM25 顺序），不加稠密腿。

**明确不在本轮**：BM25 的 trigram 分词补丁（修 CJK 的便宜补丁）不进本轮——一次只变一个变量，它若有用另开一轮单测。

## 受测系统与对照（本文件写下后冻结）

| 代号 | 系统 | 候选生成 | 说明 |
|---|---|---|---|
| S2-cal（control） | 现行线上系统 | BM25 全部命中 | 在新题集上**新鲜跑**（新 JEV 调用）；v1+v2 的已知成绩（50/55 + 39/45 = 89/100）只作回归参照，不重跑 |
| S5a（hosted） | BM25 + 托管稠密腿 + JEV@0.8 | 同上 + OpenAI `text-embedding-3-small` top-8 | 主流代表路线。**本轮只注册、不跑**：等 Dai 经安全入口提交 OpenAI key 后由后续任务接线运行；key 未到位前 runner 里该后端只能报“等待连接器”错误，不许用任何其他方式取 key |
| S5b（local） | BM25 + 本地稠密腿 + JEV@0.8 | 同上 + BGE-M3（`BAAI/bge-m3`，sentence-transformers，CPU）top-8 | 自托管路线；模型版本、库版本在 `round3-setup.md` 里钉死并记录 |

稠密腿口径（两臂一致）：向量 = 模型 dense 输出，L2 归一化，余弦相似度 = 点积；块文本用 onboard 存的原文，与 JEV 看到的文本相同；问题不加指令前缀（BGE-M3 官方用法不需要）。

## 题库 v3（规格在本文件写下后冻结，新题在预注册之后编写）

- 语料不变：冻结的 Momo Ceramics 5 页，不许改。
- **新题 50 道（headline 集）**，全部针对同一批冻结英文页面；可答题的期望事实一律用页面里的英文事实串（与 v1 中文组 G 的做法相同——抽取式回答引用的是英文块，评分按英文事实串匹配）：
  - **英文改写 ×20**（组 `paraphrase2`）：措辞刻意避开页面词汇（同义词、换句式、口语化），难度下限是 v1/v2 的 B 组。其中**至少一半与目标块之间除停用词外零内容词重合**——写后用程序核验（内容词口径：`app.tokenize` 的输出去掉常见英文功能词后的词集；核验结果逐题记录在题库文件的 `target_overlap` 字段）。
  - **中文 ×20**（组 `zh2`）：可答 12（直问与改写混合）、近似陷阱 4、无答案/动作边界 4。
  - **日文 ×10**（组 `ja`）：可答 6、近似陷阱 2、无答案/动作边界 2。
- Headline 指标组就是这三组（合计即新题集 50 题）。**兜底完整性集** = 新题集中全部非答题（期望 fallback / handoff 的题，共 12 题：中文 8 + 日文 4）。
- v1+v2 的 100 道核心题（v1 英文核心 55 + v2 新增 45，不含 v1 中文探索组 5 题）是 S5 两臂的**回归集**：入选臂必须重跑这 100 题，与 S2-cal 已知 89/100 对照；与新题分数分开报告，永不合并。
- 新题编写规则（同前两轮）：可答题的期望事实必须逐字能在期望来源页的知识块中找到，逐题程序核验；陷阱/无答案题的“缺失事实”必须在全部 5 页原文中检索确认不存在；任何一道新题不得与 v1+v2 任一题重复或轻微改写（归一化文本 + 词面重叠双重筛查，中文/日文按字符 n-gram 筛查跨语言同义重复）；新题由 agent 在本预注册之后、任何第三轮模型调用之前编写（文件 `questions-v3-additions.json`；合并版 `questions-v3.json` 带 `set` 字段）。

## 候选池召回诊断（本轮的 headline 诊断）

- **金块**定义：归一化文本包含 ≥1 个期望事实串的知识块（仅对可答题定义；非答题金块为空、该项记 n/a）。
- 逐题记录：候选池大小、金块数、金块进池数、池召回率（进池金块 / 全部金块）、有无任一金块进池。control 与每个 S5 臂都记——这一项回答的是“答错的题里，有多少是金块根本没进池（召回问题）、多少是进了池但 JEV 没放行（决策问题）”。

## 评分口径（与前两轮逐字一致）

- hit / partial / miss 三档，复用 `run_s2.py` 的 `verdict_for`（与 `run_baseline.py` / `run_s1.py` 逐字一致）：答题组看行为、来源命中、期望事实出现 ≥ 一半；兜底/转人工组行为对了即 hit，返回了答案文本即 miss。
- 陷阱/人工边界组的全部 miss 由人工逐条复核：回答是原文逐字引用（无害引用）、编造事实、还是声称已执行操作。复核结论写进成绩单。**任何陷阱/人工边界题出现编造 = 该臂一票否决**，不论总分。
- 延迟口径：题目间 4 线程并行（同前两轮），每题延迟记“服务时间”= 问题 embedding 耗时（control 为 0）+ 本地 BM25 耗时 + 该题 JEV 调用耗时，不含线程排队。**本地臂的延迟在本 VM 上测**（共享约 1.5 CPU / 6 GB 内存），成绩单必须标注这比专用部署环境悲观；采用线的延迟项按此口径判，硬件保留意见同时记录。
- 成本口径：JEV 按响应 usage 实测 input tokens × $0.042/1M（output 免费），各臂相同、不计入增量；增量成本 = 该臂的 embedding 调用费（本地臂 = 0；托管臂按 OpenAI 官方价、运行时记录）。

## 决策规则（最终版，跑完照此判定）

**某 S5 臂 ADOPT-eligible（可建议把稠密腿并入线上候选生成，仍需 Dai 最终点头才动 app.py）——以下六条全部满足才算：**

1. 新题集命中率 ≥ control 新题集命中率 **+ 20 个百分点**（百分点口径同前两轮规则）；
2. 新题集兜底完整性 ≥ 90%（12 题中至少 11 题行为正确）；
3. 编造 = 0（人工复核无编造事实、无声称已执行操作）；
4. 回归集（v1+v2 共 100 题，该臂重跑）总命中 ≥ 87/100（相对 S2-cal 已知 89/100 下降 ≤ 2 题）；
5. 新题集每题延迟 p50 ≤ 3 秒（本地臂按本 VM 实测口径判，硬件保留意见记录在案）；
6. 增量成本 ≤ $0.01 / 题。

**两臂之间（两臂都跑完后才可写最终判定）：**

- 两臂都 eligible 且新题集命中题数差 ≤ 3 题 → 推荐**本地 BGE-M3**（零边际成本、不多一个供应商）；
- 两臂都 eligible 且托管臂新题集命中领先 > 3 题 → 推荐**托管**；
- 只有一臂 eligible → 推荐该臂；
- 两臂都不 eligible → 混合检索不采用，线上维持 S2-cal，逐条记录卡在哪条。

**S5a 未跑之前，最终判定不许写**：本轮（S5a 挂起）结束时，README 与成绩单只能记录 control 与 S5b 的成绩和逐条对照进度，并明示“最终判定待 S5a”。
